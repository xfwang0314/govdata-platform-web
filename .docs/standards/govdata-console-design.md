# 政务数据中台控制台设计基线

本规范适用于数据源、数据资源、元数据、采集、交换、质量、本体、策略等后台工作页面。事实实现位于 `apps/web-antd/src/styles/govdata-console.css`，颜色必须继续复用 Vben / Ant Design 主题变量，以保证亮色、暗色和租户主题一致。

## 1. 设计原则

- 采用专业、克制的控制台风格，信息层级优先于装饰。
- CRUD 资源页使用页头、紧凑筛选、工具栏和表格，不改造成指标卡 Dashboard。
- 目录型页面使用导航区与工作区，通过背景和细边界分区，不使用两个悬浮大卡片。
- 主操作每个页面只保留一个；高频行操作直接展示，低频和危险操作收进“更多”。
- 状态使用小面积色点和文字，颜色只表达语义，不使用大面积高饱和底色。

## 3. 页面模式

### 资源管理页

不需要长期解释的资源页直接进入工作区，不保留 `Page` 标题和说明；主操作放在表格工具栏。列表必须复用项目标准 `useVbenVxeGrid` / `BasicTable`，筛选表单位于表格内部，使用 `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`、标签宽度 80px 和默认折叠行为的基线配置，不得自建筛选栏或以页面 CSS 模拟表格。名称是第一视觉层级，稳定编码使用等宽弱文字。连接状态使用 `ConsoleStatus`。

### 目录工作区

使用 `gov-metadata-workbench`：左侧 `gov-resource-navigator` 使用“数据库 → 数据源连接 → 实际 Catalog/Schema → 表与视图 → 列”的树定位对象；连接按展开加载，不再单独使用数据源下拉框，右侧 `gov-metadata-workspace` 承载筛选、列表和详情。元数据导航采用组件库 Splitter，默认宽260px、最小宽200px；移动端转为上下布局。

元数据目录直接进入工作台，不保留独立页面标题；右侧查询条高 64px，查询与重置紧跟筛选项；表格工具栏高 46px，在同一行显示当前范围、结果数量、刷新和列设置。三栏模式导航默认260px、预览默认340px，支持拖动与收起；1280px以下预览改为抽屉，768px以下导航切换为上下布局。禁止恢复常驻功能介绍、独立筛选 Card、独立统计行或全屏按钮。

筛选工具条遵循 8 / 12 / 16px 间距节奏。桌面输入框和下拉框的有效输入宽度统一为 260px；控件高度、字号、边框和行高只由全局 Ant Design Token 控制，单选 Select、多选 Select、输入框及日期选择器不得在页面内单独覆写；1280px 以下输入宽度统一为 220px；窄工作区允许等宽双列换行，但不将资源目录堆叠到表格上方。查询和重置作为一个操作组，与筛选项至少保持 16px 组间距。

### 表单与详情

新建、编辑表单按信息相关性分组，使用分隔线而非多层 Card。详情抽屉先展示对象身份和状态，再展示属性、字段及影响关系。技术名、资产编码和连接目标使用等宽字体，并提供溢出提示。

## 4. 复用边界

- 优先复用 `Page`、`useVbenVxeGrid`、`useVbenForm`、Ant Design Token。
- `ConsoleStatus` 用于跨领域重复出现的状态点；业务状态到语义色的映射仍由页面负责。
- 不为单页面布局创建空壳组件；只有跨两个以上模块稳定复用的模式才进入公共组件。
- 禁止新增页面专属硬编码品牌色、无意义渐变、玻璃拟态、大面积阴影和满屏圆角 Card。

## 5. 第二轮审查后的强制约定

- 所有资源页使用项目标准 `BasicTable` 外观，表头由 `headerAlign: 'center'` 统一居中并复用组件库的加粗字重，表头高度 44px，数据行高度 48px；名称、说明、技术名和编码等长文字列默认左对齐，状态、枚举、时间、布尔值和操作列居中，数值比较列按需要右对齐。名称用正文 14px，技术名、编码、日期等辅助信息不小于 12px。
- 标识名称与稳定编码分别使用独立列，不在一个单元格内上下堆叠；开关型状态默认只展示开关，避免重复显示“已启用 / 已停用”；状态与发生时间需要同时表达时，优先在同一行排列。
- 表格 TD 正文默认完全继承 `BasicTable` 的字体、字号、字重和文字色；除可点击链接、语义状态点、截断和等宽技术标识外，禁止在单个业务页面为 TD 单独设置 `text-xs`、`text-sm`、弱色或强调字重。
- 查询区只用一条细边界连接工具栏，不加粗背景隔带；少量筛选项完整显示，不提供无意义的折叠按钮。
- 不能使用 `BasicTable` 的并列工作区表格，使用全局 `gov-console-query-bar`、`gov-console-section-toolbar` 和 `gov-console-table`；查询栏高 64px、工具栏高 46px，表头与行高仍遵循同一基线，禁止在页面内复制表格字体或表头样式。
- 修订、审计等依赖具体资源的历史页，主页面应先用可搜索的资源列表定位对象；按行进入 Drawer 查看该对象的完整历史与关联问题，不要求用户输入内部 ID。
- 页面只用一层容器边界；表格和 Descriptions 已有边界时，不再套边框。Drawer 使用组件自身内边距，不叠加第二层横向 Padding。
- 类型、字段约束、数量、安全分类分级默认中性文字。连接失败等运行状态才使用语义色；不根据前端自定耗时阈值绘制告警，不给状态点加光晕。
- 导航节点高 32px、层级缩进 16px；大目录默认展开数据库分类、当前连接及第一个真实命名空间，避免一次渲染全部数据库对象。导航可拖动和收起，字段默认折叠在表下，树使用虚拟滚动。长名称可截断但必须有完整提示，字段详情允许换行。横向滚动应在工作区内，不撑宽整个页面。
- 可点击控件必须有 Hover 和可见键盘焦点；加载期间禁用冲突操作。无资源、搜索无匹配、请求失败分别表达，不显示空白加载残留。
- 表单继续复用现有表单组件、校验和权限；以分组标题和间距建立顺序，不新增装饰卡片。普通说明不升级为警告。

## 6. 验收记录与边界

第二轮已完成代码审查和减法调整，覆盖列表、导航和相关弹窗；未改后端接口与权限。浏览器当前停在登录页，尚未完成登录后真实数据在 1024 / 1440 / 1920 宽度下的截图验收，不能把代码检查当作视觉验收通过。

后续页面复用此规范时，必须补验三种桌面宽度、长名称、空数据、错误、Loading、键盘导航以及抽屉内滚动，不以构建成功替代实际页面验收。

元数据页面按职责封装资产列表、导航状态、布局、位置导航、资产概览和字段表格。列表查询和分页由列表组件管理，页面只协调范围与详情；字段选择使用所属表ID加载详情并定位字段。资产列表默认收起资产编码、命名空间、治理、安全和最近同步等辅助列，保留列设置入口。

## 元数据资产发现三栏（2026-10-28）

元数据目录采用左侧分类导航、中间分页结果和右侧快速预览，属于资产发现界面；按用户确认的设计，使用项目Ant Design组件的紧凑查询栏、卡片和Table共用一份查询状态与Pagination，不另造分页接口。左侧默认260px、预览默认340px，均可调整；1280px以下预览转为抽屉，768px以下导航改为上下布局。表和列分类数量只来自授权树；未加载连接不展示猜测值。默认卡片，支持紧凑列表；完整详情及版本保留抽屉。原有CRUD资源页继续采用BasicTable，此资产发现模式不修改其他领域页面。

## 元数据采集工作台（2026-10-28）

元数据采集采用“数据源快捷入口 + 隐藏路由工作台”。侧边栏不再展示独立的元数据采集菜单；用户从数据源列表的“采集管理”进入工作台。进入后先展示该数据源的全部采集计划，并在当前上下文完成新增、编辑、删除、立即运行和运行记录查看；不得自动打开第一条计划。数据源列表仅提供跳转，不在数据源详情中嵌套采集组件。返回数据源管理与新建计划放在同一工具栏，避免为上下文导航单独增加页面层级。

计划配置与运行记录分别使用独立的大尺寸模态框，禁止使用Tab把配置和运行历史混成一个工作区。计划模态框只负责新增、查看和编辑；运行记录模态框只负责历史查询，并在内部切换运行详情。任一时刻只打开一层模态框，禁止Modal套Modal或Modal套Drawer。删除、停止等危险操作继续使用短确认。数据源快捷入口通过`datasourceId`限定计划列表和新建计划的数据源，不复制采集业务逻辑。数据源与采集的后端模块边界保持独立。
